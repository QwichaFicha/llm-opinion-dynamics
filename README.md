# llm-opinion-dynamics

Минимальный прототип первой идеи для лабораторной: **формирование и изменение коллективных предпочтений**. Агенты Concordia выбирают между цифровым доступом и печатными книгами в вымышленной библиотеке, получают внешнюю информацию и обмениваются сообщениями по заданной сети.

**Для обсуждения с коллегами: [единый итоговый отчёт по заданию, 6 страниц](reports/assignment_report.pdf).** В нём объединены оба протокола, устройство агентов, памяти и среды, результаты проверок, сложности, полезные решения для своей библиотеки и следующие этапы. [Редактируемый исходный текст в HTML](reports/assignment_report.html).

## Новый протокол от 25.11.2026

**[Новая демонстрация](demo/discussion.html)** · **[Отчёт второго протокола](reports/deliberation_v2_report.pdf)** · **[Подробный протокол и запуск](docs/DELIBERATION_V2.md)**.

Теперь у участников есть потребности и бюджеты, последовательные факты и исправление ошибочной стоимости, собственная история аргументов. Собеседники меняются без повторов: за пять раундов каждый из шести участников встречается со всеми остальными ровно один раз. Постоянные пары, память, численные позиции и краткость профилей проверяются отдельными условиями.

**GPT-6-Luna через Codex подключена к Concordia и проверена реальными запусками.** Отдельный новый API-ключ для этого маршрута не потребовался. Это сравнение маршрутов «bonsai / API» и «Luna / Codex»: системный контекст и параметры Codex отличаются. Для чистого сравнения моделей этого недостаточно. Проходят 36 тестов; страница демонстрации автономна и не вызывает модели.

В bonsai обнаружены содержательные противоречия даже при верных полях фактов: например, 80 названо меньшей стоимостью, чем 40. Поэтому извлечение фактов и качество аргументации оцениваются раздельно. Точные цитаты: `artifacts/analysis/deliberation_manual_review_2026-11-25.json`.

## Первый этап: 21–23.11.2026

- Concordia 2.4.0, Python 3.12.14.
- 40 контрольных запусков: восемь условий по пять начальных состояний.
- Две дополнительные пробы памяти по 20 раундов.
- 27 автоматических тестов, включая ограничения частоты запросов, диагностический протокол, выбор системной роли и совместимость конфигураций памяти.
- Первый этап: 40 запусков с численной заглушкой.
- 23.11.2026: реальный пилот bonsai2-27b — 102 запроса, 102 валидных ответа, 40 325 токенов; четыре базовых условия выполнены для seed=11.
- Продолжение: 156 запросов на диагностику и точный повтор условий плюс 12 на разбор арифметической ошибки; ещё 57 735 токенов. Все четыре повторные траектории и 96 текстов ответов совпали с первым пилотом.
- Профили и память: ещё 11 симуляций, 264 запроса, 119 345 токенов, 14 минут 5 секунд; все завершились. Базовые условия теперь сопоставлены на seed 11, 22, 33; отдельно выполнено сравнение памяти и поля исходной позиции.
- Всего внешней генерации: 534 запроса, 217 405 токенов. Точные повторы и исторические baseline не считаются новыми независимыми профилями.

Проверка пригодности: 11/12 простых задач в системной роли агента. Ошибка знаковой арифметики воспроизводилась в этой роли и исчезла в проверенных примерах при нейтральной системной инструкции либо reasoning. Модель оставляем для прототипа; точные вычисления выполняем кодом. Есть чувствительность к формулировке новости и полю исходной позиции, поэтому социальные выводы требуют дальнейшей проверки дизайна и второй модели.

Работа инфраструктуры и подключение реальной LLM подтверждены. Но направление эффектов неустойчиво к численным профилям: общение увеличило разброс при seed=11 и уменьшило при seed=22/33. Длинное окно наблюдений без поля `initial_opinion` на seed=11 дало дисперсию 0.2011 против 0.3189 в базовой ячейке. Это взаимодействие двух настроек одного прототипа, а не подтверждение закономерностей поведения людей.

Дополнительная проверка 25.11.2026: [повторы аргументов и остановка динамики](docs/STAGNATION_ANALYSIS.md). После первого раунда в девяти базовых запусках с воздействием не менялись 143 из 162 позиций на отдельных шагах агентов (88,3%). Найдены и дословные совпадения с полученными репликами соседей. Техническая работоспособность подтверждена, но содержательное качество обсуждения пока не подтверждено; нужна диагностика реакции на конкретные факты и сравнение моделей. Анализ сохранённых данных не использует API.

## Как повторить и расширить LLM-эксперименты

Пилот, точный повтор и серия профилей/памяти завершены. Следующий исследовательский шаг — перестановка ролей между исходными позициями, сравнение текстового общения с численными позициями соседей и проверка собственной истории аргументов. Перед расширением определить число повторов и токенный бюджет. Просмотр готовых результатов и генерация отчётов API не используют:

```powershell
.\.venv\Scripts\python.exe scripts/build_live_report.py
.\.venv\Scripts\python.exe scripts/build_quality_report.py
.\.venv\Scripts\python.exe scripts/build_robustness_report.py
.\.venv\Scripts\python.exe scripts/build_complete_report.py
```

Для новой такой же ограниченной серии (до 102 запросов) использовать один процесс:

```powershell
.\.venv\Scripts\python.exe scripts/run_live_pilot.py --output artifacts/runs/live_pilot_repeat_01
```

Ограничитель общий внутри процесса: минимум 3.2 с между стартами, лимиты 20 RPM и 100 000 TPM по предварительным резервам, один запрос одновременно. Он не координирует другие программы и независимые процессы с тем же ключом.

Новый параметр `Config.include_initial_opinion` управляет только видимостью собственного исходного поля в контексте; текущая позиция остаётся. Значение по умолчанию `True` сохраняет старый протокол. `memory_rounds` управляет извлечением наблюдений, не их удалением из хранилища. Собственная аргументация ещё не записывается автоматически. Прежние состояния без нового флага восстанавливаются с исходным поведением.

Повтор последней ограниченной серии требует до 264 запросов:

```powershell
.\.venv\Scripts\python.exe scripts/run_robustness_study.py --output artifacts/runs/robustness_repeat_02
```

Дополнительно нужны заранее выбранные формулировки каждой новости и другие профили для проверки взаимодействия памяти и исходного поля. Параметры генерации менять отдельным условием. Точные повторы при temperature=0 не заменяют независимую вариацию профилей и промптов.

Для аналитических задач адаптер принимает явный `system_message`. По умолчанию сохранена прежняя роль участника симуляции, чтобы не менять протокол незаметно. Пример нейтрального вызова из Python:

```python
from src.models import TracedModel

model = TracedModel("live", max_calls=1, system_message="You are an accurate assistant. Return the requested JSON.")
```

Найденные ошибки и результаты всех режимов сохранены, включая неудачные ответы. Вторая модель на текущем шлюзе отсутствует: GET `/models` возвращает только `bonsai2-27b`.

### 1. Указать доступ к LLM

Локальный `.env` уже настроен для шлюза и bonsai2-27b. Для другого компьютера заполнить доступ локально:

```dotenv
LLM_API_KEY=ваш_ключ
LLM_BASE_URL=https://ftii.llm.actcognitive.org/v1
LLM_MODEL=bonsai2-27b
```

Нужен провайдер с OpenAI-совместимым `POST /chat/completions`. Ключ находится только в локальном `.env`, который исключён из Git. Если файл создаётся заново: `Copy-Item .env.example .env`.

По умолчанию лимит ответа — 300 токенов. Если провайдер требует `max_completion_tokens`, изменить `LLM_TOKEN_FIELD`. Если он не принимает `temperature`, указать `LLM_SEND_TEMPERATURE=false`.

### 2. Выполнить один реальный smoke-запуск

```powershell
.\.venv\Scripts\python.exe -m src.experiment smoke --backend live --max-calls 6 --output artifacts/runs/live_smoke_01.json
```

Это один раунд на шести агентах, максимум шесть запросов. При ошибке запуск останавливается, автоматических повторов нет. Сначала проверить `status`, число ответов, валидность JSON, задержки и `usage`, если провайдер его вернул. Лимит запросов не задаёт денежный бюджет: стоимость оценить по реальному usage и тарифу провайдера.

### 3. Провести базовые условия

После успешного smoke запустить `control`, `news_only`, `peers_only`, `combined` с одинаковыми seed 11, 22, 33, 44, 55. Пример одного запуска:

```powershell
.\.venv\Scripts\python.exe -m src.experiment run --backend live --condition combined --seed 11 --max-calls 24 --output artifacts/runs/live_combined_11.json
```

Менять условие, seed и имя выходного файла. Полный базовый набор — 20 запусков, до 480 запросов без повторов. Начать с одного seed для всех четырёх условий и оценить расход, затем расширять серию. Пока ключ не заполнен, эти команды не выполнять.

### 4. Проанализировать результаты и дополнить отчёт

Проверить дрейф в `control`, отдельно оценить влияние новости и общения, сравнить с численной моделью. После этого добавить `combined_memory4`, `combined_complete`, `combined_segregated`. Потребуются повторы генерации: пять seed исходных профилей не заменяют независимые повторы LLM.

Текущий `scripts/build_report.py` читает историческую серию `offline_v1`. Он не включает новые live-запуски автоматически. Для live-пилота используется отдельный `scripts/build_live_report.py`; исходный отчёт сохранён как протокол первого этапа.
