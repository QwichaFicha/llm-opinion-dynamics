# Второй протокол: конкретные факты и новые собеседники

Дата разработки и начала пилота: 25.11.2026. Основание — подтверждённая слабая динамика и повторение общих аргументов в первом сценарии. Старые опыты и отчёты сохранены; новый протокол не является их точным повтором.

## Участники и встречи

Шесть участников: студент, родитель, библиотекарь, учитель, пенсионер и разработчик. Теперь у них указаны потребности, условия доступа, критерии выбора и бюджет. Порядок профилей переставляется воспроизводимо по seed 41. Исходные численные мнения не навязываются: в раунде 0 каждый агент формирует первую позицию по общим сведениям.

Далее пять раундов попарных встреч по круговой турнирной схеме. В каждом раунде ровно три непересекающиеся пары. Каждый участник встречается с каждым из пяти остальных ровно один раз. Повторная встреча в основном условии невозможна; для шести участников шестой такой раунд уже потребовал бы повтора или увеличения группы.

Встреча реализована синхронно: каждый видит последнее публичное сообщение нового собеседника из предыдущего раунда. Затем все формируют новые ответы. Это один обмен позициями за раунд, без нескольких реплик туда-обратно в одной встрече. Собеседник не видит ещё не сделанный новый ответ другого агента. Такое расписание исключает преимущество последнего вызванного агента.

## Новые сведения по раундам

| Раунд | Запись | Содержание |
| --- | --- | --- |
| 0 | BASE_ACCESS, BASE_COST, BASE_SERVICE | Цифровой доступ требует интернета, стоит 120 единиц против 80 у печатных книг; перечислены особенности обоих вариантов |
| 1 | E1_OFFLINE | Проверенное обновление позволяет читать загруженные цифровые книги без интернета |
| 2 | E2_FACADE | Фасад перекрашен; доступ, стоимость и условия чтения не меняются |
| 3 | E3_COST | Официальный бюллетень сообщает цифровую стоимость 40 вместо 120 |
| 4 | E4_CORRECTION | Исправление: в E3_COST забыты лицензии, правильная стоимость 140; прежняя запись отозвана |
| 5 | E5_SUPPORT | Появились обучение работе с устройствами и выдача устройств напрокат; домашний интернет и стоимость не меняются |

Все сведения вымышленные. Их последовательность и правильные проверяемые факты определены до основной серии. Правильные ответы не передаются модели скрытым полем: внутреннее поле `updates` используется только для численного контроля и проверки, из промпта оно удаляется.

## Ответ и память

Ответ содержит позицию `opinion`, публичный аргумент `message`, использованные записи `evidence_ids`, краткое объяснение `reason` и три проверяемых факта `beliefs`: наличие офлайн-доступа, цифровую и печатную стоимость. Сохранение мнения допустимо. Требовать сдвига или нужной исследователю стороны нельзя.

Память Concordia хранит официальные сведения, сообщения собеседников и собственные прошлые ответы. В контекст извлекаются все официальные записи, последнее сообщение текущего партнёра и собственная история аргументов. Более старые сообщения прежних партнёров сохраняются, но напрямую в промпт не включаются. Чужие численные позиции в основном условии не показываются.

Проверяемые факты позволяют обнаружить игнорирование исправления. Совпадение этих трёх полей с эталоном не доказывает правильность аргумента целиком. Нужна также содержательная проверка текста, отношения к нерелевантной новости, персональных критериев и повторов.

## План сравнений

| Условие | Отличие от основного | Вызовы на пять раундов и начальную позицию |
| --- | --- | ---: |
| rotating_text | Новые пары, подробные профили, собственная история, только тексты собеседников | 36 |
| fixed_text | Те же пары во всех раундах; первый раунд совпадает с основным | 36 |
| rotating_no_own | Собственная аргументация скрыта, текущее число сохранено | 36 |
| rotating_numeric | Добавлены численные позиции собеседников | 36 |
| rotating_role_only | Вместо подробного профиля только название роли | 36 |

Дополнительно 24 одношаговые диагностики: каждый из шести профилей получает базовые факты без новости, релевантное изменение, нерелевантную новость или ошибочную стоимость с исправлением. Правильная позиция не предписывается. Проверяются факты и парные реакции; диагностический набор небольшой и не измеряет общий интеллект модели.

План для bonsai2-27b: максимум 204 вызова. Для второй модели: те же 24 диагностики и основной сценарий, максимум 60 вызовов. Полный набор условий второй модели ещё не является частью этой сравнительной серии. Точные исходные планы и снимки кода сохраняются до запусков в `protocol.json` и `source_snapshot/`.

## GPT-Luna через Codex

Выбран второй доступный маршрут из задания: `gpt-6-luna` через установленный `codex exec`. Первый арифметический запрос вернул −0,04. Затем адаптер `CodexModel(LanguageModel)` подключён к `ConcatActComponent` Concordia; короткий запуск 12 вызовов завершился.

Каждый вызов — отдельный `--ephemeral` запуск с `--sandbox read-only`, `--ignore-user-config` и схемой ответа. Пользовательская авторизация используется на месте; токены входа не извлекаются и не копируются. Запрошены отсутствие инструментов и только итоговый JSON; неожиданные инструментальные события останавливают запуск. Это не прямой OpenAI-совместимый HTTP API.

У Codex остаются собственные системные инструкции, форматирование вывода и настройки генерации; температура не выравнивается с bonsai API. Поэтому сравнение относится к двум конфигурациям «модель + маршрут», а не даёт чистого рейтинга моделей. Служебный контекст Codex заметно увеличивает входные токены, даже при коротком пользовательском запросе. CLI-вызов также нельзя безусловно считать одним серверным запросом: возможны внутренние повторы клиента.

Codex использует лимиты действующего доступа. Отсутствие отдельного API-ключа не означает неограниченный бесплатный API. Документация режима: [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode).

## Бесплатный отдельный API при необходимости

Создать ключ можно в [OpenRouter](https://openrouter.ai/settings/keys). Нужен конкретный доступный идентификатор из [каталога бесплатных моделей](https://openrouter.ai/collections/free-models/), с ценой 0 за вход и выход и суффиксом `:free`. Универсальный `openrouter/free` может менять модель между запросами и для сравнения не подходит. Дневную квоту и доступность нужно проверить для своего аккаунта; бесплатная серия может не поместиться в лимит одного дня. [Ограничения сервиса](https://openrouter.ai/docs/api_reference/limits).

Шаблон `.env.compare.example` копируется в локальный `.env.compare`. Этот файл исключён из Git. Ключ в чат и в журналы передавать не нужно. Дополнительный прямой API остаётся необязательным: основной второй маршрут уже проверяется через Codex.

DeepSeek-V4-Pro был первоначально предложен как отдельная модель с OpenAI-совместимым API. Бесплатность этого API не установлена; официальный тариф опубликован отдельно. Чтобы начать сравнение без нового платного подключения, текущая серия использует Luna. [Модели и тарифы DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/).

## Запуск и ограничения

```powershell
# Полная техническая проверка с заглушкой, без сети:
python scripts/run_deliberation.py --backend stub --suite full --output artifacts/runs/my_v2_stub
# Новая ограниченная серия через существующий шлюз, максимум 204 вызова:
python scripts/run_deliberation.py --backend bonsai --suite full --output artifacts/runs/my_v2_bonsai
# Сравнительная серия Luna через Codex, максимум 60 CLI-вызовов:
python scripts/run_deliberation.py --backend codex --suite compare --output artifacts/runs/my_v2_luna
```

Использовать интерпретатор проекта и новые пути. Нужен установленный и авторизованный Codex CLI для соответствующего backend. Лимит API применяется внутри процесса: последовательные запросы, существующий ограничитель 20 RPM / 100 000 TPM, без автоматических повторов приложения. Исходный `.env` не перезаписывается; лимит ответа 600 токенов задаётся только текущему процессу новой серии.

Первый bonsai smoke остановился на 11-м вызове: объяснение имело 421 символ при запрошенном максимуме 350. Он сохранён как неудачный запуск. Для основной серии ограничения 600/350 учитываются как мягкая проверка краткости, текст до 2000 символов сохраняется; ошибки схемы, типов и диапазона останавливают запуск. Повторный bonsai smoke завершился за 12 вызовов. Такое изменение явно записано в новых протоколах.

Сложность: смена пар — 2/5; отделение хранилища от контекста и собственной истории — 3/5; CLI-интеграция и учёт служебного расхода — 3/5; содержательная оценка — 4/5. Это инженерные оценки, человеко-часы не измерялись. Один сценарий и одна перестановка профилей пока не дают статистической устойчивости, причинного объяснения поведения людей или доказательства превосходства модели.
